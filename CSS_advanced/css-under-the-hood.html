البنية التحتية لـ CSS (Under the Hood)

التوثيق المعماري الدقيق لكيفية تفاعل محرك تصيير المتصفح (Rendering Engine) مع الأوامر المنخفضة المستوى (Low-level) للـ CSS، بعيداً عن التجريد وإطارات العمل.

1. نموذج الصندوق والرياضيات (The Box Model Engine)

*, *::before, *::after { box-sizing: border-box; }

إعادة برمجة حسابات المتصفح (Override Default Calculations)

الميكانيكية: الوضع الافتراضي للمتصفح (content-box) يقوم بحساب العرض الفيزيائي للعنصر كالتالي: العرض المكتوب + مساحة الـ Padding + مساحة الـ Border. هذا يكسر أي نظام شبكي (Grid) يعتمد على النسب المئوية لأن العنصر يتمدد للخارج.

الأمر border-box يتدخل في خوارزمية الرسم (Painting Algorithm) ويجبر المحرك على استيعاب الـ Padding والـ Border نحو الداخل. إذا أعطيت العنصر عرض 33.33%، سيبقى فيزيائياً 33.33% من الشاشة بغض النظر عن الحشوات الداخلية، مما يضمن دقة الرياضيات في الشبكات.

2. المتغيرات وبيئة التشغيل (Runtime Evaluation)

:root { --color-primary: #d73953; } [data-section-theme="dark"] { --bg-color: #000000; }

التقييم الديناميكي ونطاق المتغيرات (Scope & Dynamic Repaint)

الميكانيكية: خصائص CSS المخصصة (Custom Properties) تختلف جذرياً عن متغيرات SASS. المتغير هنا ليس نصوصاً تُستبدل قبل التشغيل، بل هو عقدة حية (Live Node) في نموذج كائنات CSS (CSSOM).

الـ :root يزرع المتغير في أعلى هرم الـ DOM. ولكن عندما نستخدم [data-section-theme="dark"] لإعادة تعريف المتغير، يقوم المتصفح فوراً بعملية Repaint (إعادة تلوين بكسلات الشاشة) للأبناء دون الحاجة لإجراء Reflow (إعادة حساب أبعاد الصفحة)، مما يجعل هذه الطريقة الأكثر كفاءة (Performant) هندسياً لبناء وضع ليلي (Dark Mode).

3. هندسة الشبكات القديمة (Legacy Grid & Flow Detachment)

[class*="col-"] { float: left; width: 33.33%; }

الفصل عن التدفق (Detaching from Normal Flow)

الميكانيكية: محدد السمة [class*="col-"] هو أداة بحث (Regex-like) تستهدف أي عنصر يحتوي كلاسه على هذه السلسلة. الأمر float يقوم حرفياً بسحب العنصر من خوارزمية الترتيب العمودي الطبيعي (Block Formatting Context) للمتصفح، ويدفعه لأقصى اليسار، مما يسمح للعناصر الأخرى بالتكدس بجانبه بناءً على النسب المئوية.

.row::after { content: ""; display: table; clear: both; }

تنظيف الذاكرة البصرية (The Clearfix Hack)

الميكانيكية: لأن الـ float يفصل العناصر عن التدفق، العنصر الأب (.row) يعتقد رياضياً أنه لا يحتوي على أبناء، فينهار ارتفاعه إلى 0px. هذا الانهيار يدمر بقية تخطيط الصفحة.

الحل هو حقن عنصر زائف (Virtual Element) في نهاية الأب. الأمر clear: both يخبر محرك التصيير: "ممنوع تواجد أي عنصر طافٍ بجانب هذا العنصر". وبما أننا جعلناه display: table (ليأخذ العرض كاملاً)، فإنه يُجبر الأب على التمدد للأسفل لابتلاع جميع أبنائه الطافيين، مما يعيد الاستقرار للشبكة.

4. التموضع واختراق الـ DOM (Positioning & Virtual Nodes)

.card-work { position: relative; } .card-inner { position: absolute; top: 0; bottom: 0; left: 0; right: 0; }

سياق التموضع وتمدد الإحداثيات (Positioning Context & Stretch)

الميكانيكية: position: absolute يمحو العنصر تماماً من حسابات المساحة. ولكي لا يطير العنصر ليعتمد على الشاشة بالكامل (Viewport)، نستخدم position: relative في الأب. هذا الأمر لا يغير مكان الأب، لكنه يزرع نقطة ارتكاز إحداثية (Coordinate Origin) للأبناء.

الخدعة المعمارية هنا هي إعطاء الـ (Top, Bottom, Left, Right) جميعها قيمة صفر. هذا يخلق تناقضاً رياضياً يُجبر محرك المتصفح على تمطيط (Stretch) العنصر المطلق ليغطي 100% من مساحة الأب دون استخدام خصائص الـ Width والـ Height.

.card-title a::after { content: ""; position: absolute; top: 0; bottom: 0; left: 0; right: 0; }

توسيع منطقة النقر (Hit-Testing Override)

الميكانيكية: بدلاً من الاعتماد على الجافاسكريبت لجعل البطاقة بأكملها قابلة للنقر، نقوم بحقن عنصر زائف (Virtual Node) داخل الرابط <a> ونعطيه تموضعاً مطلقاً يمتد ليغطي البطاقة الأم بالكامل. خوارزمية التقاط النقرات (Hit-Testing) في المتصفح ستسجل أي نقرة على هذه الطبقة الشفافة وتمررها مباشرة للرابط، مما يعزز تجربة المستخدم (UX) بكود نظيف جداً.

.card-quote::before { content: "\201C"; z-index: -1; }

العمق السلبي والتسلسل الهرمي للطبقات (Z-Axis Stacking Context)

الميكانيكية: الـ DOM ثنائي الأبعاد (X, Y). خاصية z-index تتدخل في المحور الثالث (Z-axis) للتحكم في الطبقات. القيمة -1 تقوم بترحيل العنصر إلى طبقة خلفية رياضياً خلف محتوى العنصر الأصلي. هذا يضمن أن علامة الاقتباس التجميلية لن تمنع المتصفح من تحديد النص (Text Selection) أو حجب النقرات.

5. التسريع العتادي والفيزياء (Hardware Acceleration & Physics)

.card-image img { transition: transform 0.3s cubic-bezier(0.17, 0.67, 0, 1.01); } .card-work:hover .card-image img { transform: scale(1.2); }

تجاوز المعالج إلى كرت الشاشة (Bypassing CPU via GPU Compositing)

الميكانيكية: تكبير صورة باستخدام width و height يجبر المعالج (CPU) على إعادة حساب التخطيط (Reflow) لكل عناصر الصفحة، مما يسبب تقطيعاً (Jank) في الأداء. الأمر transform مختلف تماماً؛ فهو يمرر العملية مباشرة إلى كرت الشاشة (GPU) في مرحلة التجميع (Compositing Phase).

منحنى بيزيه (Cubic-Bezier): بدلاً من الحركة الخطية الجامدة، هذه الدالة الرياضية ترسم منحنى للسرعة على محورين (الوقت مقابل التقدم). القيمة 1.01 تعني أن الحركة ستتجاوز الهدف النهائي رياضياً بنسبة 1% قبل أن ترتد للخلف (Snap back)، مما يخلق إحساساً فيزيائياً عضوياً (Organic physics) للتأثير.
